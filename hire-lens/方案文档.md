# HireLens 招聘决策工作台 · 方案文档

## 1. 需求分析：场景 · 痛点 · 用户

### 1.1 目标场景

面向**一次招聘的完整流程**——从粘贴 JD、导入简历，到人工审核、电话沟通、面试邀约、综合评估归档。典型使用者是**单人操作的 HR / 招聘负责人**（无需 ATS 系统），也可能协同一位面试官。

### 1.2 真实痛点

| 痛点    | 现状               | 本产品如何缓解                          |
| ----- | ---------------- | -------------------------------- |
| 初筛耗时  | 逐份读简历、凭感觉打分，标准漂移 | 模型整理统一维度，逐维度给分+原文引用，HR 复核即可      |
| 黑箱难复核 | AI 只给总分，无法追溯依据   | 每条结论回原文，点引用跳原文高亮                 |
| 隐私风险  | 简历含姓名/手机/证件号，易泄露 | 评分前强制脱敏；联系方式单独存放，不进评分上下文         |
| 工具割裂  | 解析、评分、发邮件分散在多个系统 | 一个工作台串起导入→评分→审核→会议→邀约→归档         |
| 决策权不清 | 不知是该信 AI 还是自己    | AI 只做整理与参考，**进面、淘汰、邀约全部由 HR 决定** |

### 1.3 目标用户

- **主用户（HR）**：全流程主导者，负责定标准、审核、发邀约、决策。
- **协同（面试官）**：在「综合评估」页补充面试记录证据。
- **被动用户（候选人）**：只接收脱敏后的邀约邮件，不涉及任何自助操作。

## 2. 产品目标与定位

- **核心定位**：AI 是「整理员 + 打分参考」，不是「决策者」。系统不自动淘汰任何人。
- **四条硬性原则**（贯穿全产品）：
  1. **不预置模板**：一切从 HR 粘贴的 JD 开始，维度由模型按内容生成，HR 增删改。
  2. **不写死指标**：页面不展示任何未实测的准确率 / 耗时 / 成本 / 人名。
  3. **示例标注**：所有演示数据明确标注「合成示例」。
  4. **去术语化**：面向 HR 的首页与界面不出现 Agent、RAG 等技术黑话，改用「AI 解析 / 模型 / 证据」等易懂表达。
- **新用户引导三句话**：从哪开始（创建招聘任务）→ 当前做什么（导入简历并评分，状态徽章实时显示）→ 做完去哪里（审核→邀约→综合评估→导出 Markdown 归档）。

## 3. 智能体核心能力（能力拆分 / Skill 映射）

按职责拆成四个可独立调用的能力，每个都**人在回路（human-in-the-loop）**，模型输出可解释、可被 HR 覆盖。

### 3.1 JD Parser（岗位解析）

- **输入**：HR 粘贴的任意岗位 JD 文本。
- **输出**：岗位名 / 职级、硬性要求清单（带关键词）、软素质线索、3–6 个建议初筛维度（权重、最低参考线、证据关键词）。
- **人机协同**：输出是「建议」，HR 可改名、改说明、调权重、增删、调最低参考线；校验通过（3–8 项、权重合计 100%）才锁定。

### 3.2 Resume Parser（简历解析 + 脱敏）

- **输入**：文字型 PDF / DOCX 或粘贴正文（每批 ≤10，每任务 ≤30）。
- **输出**：结构化简历文本、**脱敏版本**（姓名/手机/邮箱/证件号掩码）、**单独提取的联系方式**（仅用于邀约，不进评分上下文）。
- **人机协同**：脱敏结果弹窗确认后，才开始评分；HR 可随时点「原文」复核（本地保留掩码前内容，不上传）。

### 3.3 Candidate Matching & Scoring（匹配与打分卡）

- **输入**：已确认脱敏的简历 + 已锁定的维度口径。
- **输出**：逐维度分数、原文引用句、匹配分类（较匹配 / 部分可迁移匹配 / 低匹配 / 材料不足）、加权总分、硬性条件「已满足/待核实/未满足」。
- **关键规则**：
  - 仅在**材料不可读、关键信息缺失、信息冲突**时记为 `null`：`null` 不计入总分、不折算为 0，且该候选人**不可直接选入面试**。
  - 维度无证据 → 低分并标注「证据不足」，不直接判能力不足。
  - 排名**仅辅助阅读**，进面由 HR 勾选。
  - 进入面试前可**人工重评**，历史评分保留。

### 3.4 Interview Scheduler（面试安排与邀约）

- **输入**：电话评估合格的候选人、HR 配置的 SMTP、面试日期。
- **输出**：腾讯会议号 + 入会链接 + 自动开启纪要转写（模拟）、邀约邮件模板、日历邀请（.ics）。
- **人机协同**：生成会议后由 HR 在行内确认；邮件模板自动生成，HR 填面试日期，**发送前预览并二次确认**收件人/时间/链接；发送超时**不自动重试**，标记「待核实」。

## 4. 工作流程设计（状态机）

```
创建任务 → [JD 解析] → 确认锁定标准 → [简历导入] → 脱敏确认 → [后台评分]
   → [筛选结果] HR 勾选进面 → [人工审核] 定 P0–P3 + 电话评估
   → 电话合格 → [会议纪要/会议链接] → [邀约邮件]
   → [综合评估] 召回证据、改分、定结论 → 归档 → 导出 Markdown
```

- **后台 Worker**：评分在后台运行，离开当前页面不中断，完成自动刷新；中断/失败可在首页集中提示并一键重试。
- **状态页**：只检查本地配置（存储、SMTP、解析库、版本校验、隐私），**不调用任何模型**。

## 5. 关键设计决策（Why）

1. **脱敏先于评分**：隐私合规第一道闸；联系方式与评分文本物理分离，避免"评分模型看到候选人身份"带来的偏见与泄露。
2. **null 而非 0**：材料不可读/冲突时给 0 会不公平地拉低总分、还可能被误判淘汰；`null` 不计入、不折 0，强制 HR 先复核材料。
3. **不自动淘汰**：排名只是阅读辅助，系统永不替 HR 做"拒绝"动作，降低算法歧视与责任风险。
4. **进面前可重评且保留历史**：标准锁死不代表候选人分数锁死，给 HR 纠错空间，同时留痕可审计。
5. **邮件/面试材料与评分上下文隔离**：避免邀约内容污染评分公正性。
6. **可解释优先于精准**：每条分数都带原文引用，先让 HR 信任过程，再谈分数高低。

## 6. 工程、异常、隐私与生命周期

### 6.1 工程

- 评分交给后台 Worker，长任务不阻塞界面。
- **乐观锁版本校验**：保存前比版本，旧版本保存返回 `409`，提示刷新重试。
- 状态页只读配置，不触模型。

### 6.2 异常处理（失败原因 + 恢复动作）

| 异常      | 页面提示      | 恢复动作                |
| ------- | --------- | ------------------- |
| 模型调用失败  | 「模型调用失败」  | 检查网络 → 任务内一键重试      |
| 证据检索不可用 | 「检索服务不可用」 | 首页集中提示 → 一键重试，不重复扣分 |
| 发送超时    | 标记「待核实」   | 不自动重试，HR 人工核实后处理    |

### 6.3 隐私与生命周期

- 邮箱与 SMTP 授权码**加密存储且不写入任何日志**。
- 访问链接**可随时撤销**，撤销即失效。
- **永久删除须先归档**：归档 → 恢复期 → 输入任务名确认；删除同步清理文件、向量与通知记录。
- 归档任务支持 30 / 90 天自动清理，可配置。

### 6.4 明确**不**做（范围边界）

短信、Offer 发放、视频面试、ATS 对接、多租户、OCR、转写、模型微调、候选人自助匹配。

## 7. 演示与验收路径（对应原型）

打开 `hirelens.html`：

1. 首页 → **载入合成示例任务**（5 位虚构候选人，覆盖较匹配/可迁移/低匹配/材料不足/信息冲突五类）。
2. 简历导入 → 确认脱敏 → 开始评分（后台运行，含冲突候选人记为 null）。
3. 筛选结果 → 看逐维度分数与原文引用，勾选进面（null 不可选）。
4. 人工审核 → 定 P0–P3、填电话、结果选「合格」。
5. 会议纪要 → 生成会议号+链接+转写；邮件 → 填日期、预览二次确认、发送（导出 .ics）。
6. 综合评估 → 召回证据、低置信度标注、定结论、归档、导出 Markdown。
7. 候选人对比 → 按硬性条件分组比加权总分。
